Skymarshal is a third-party Bluesky archive-management utility. It is
not affiliated with Bluesky Social, PBC, and is not a Bluesky client;
you cannot post or browse the timeline from Skymarshal. The app reads
the user's own content via the public AT Protocol XRPC endpoints
(bsky.social and public.api.bsky.app), analyzes it locally, and lets the
user delete their own posts/replies/reposts/likes or unfollow accounts
they currently follow.

There is no server I operate. There is no account on my end. There is
no off-device usage analytics or tracking. The user signs in with a Bluesky-issued app
password (a separate disposable credential, generated at
bsky.app/settings/app-passwords); their primary password never enters
my app or my infrastructure.

Deletion uses com.atproto.repo.deleteRecord, a documented public
lexicon in the AT Protocol specification:
https://docs.bsky.app/docs/api/com-atproto-repo-delete-record
The app only ever deletes records in the signed-in user's own
repository, the same operation the official Bluesky app performs when
a user deletes a post; Skymarshal adds search and batching on top.

New in 1.1: the app also reads com.atproto.repo.listRecords, another
documented public lexicon:
https://docs.bsky.app/docs/api/com-atproto-repo-list-records
It is used only against the signed-in user's own repository, to list
their own like records. This is necessary because a like on a post
whose author has since deleted their account or been suspended is
omitted from app.bsky.feed.getActorLikes — the feed endpoint returns
hydrated post views, and such a post cannot be hydrated. The like
record still exists in the user's repository. Reading the repository
directly is the only way to show the user those likes so they can
delete them. No other user's repository is ever read this way.

To test:
  1. Create or use an existing Bluesky account at bsky.app
  2. Generate an app password under Settings → App Passwords
  3. Launch Skymarshal, enter handle (e.g. yourname.bsky.social) and
     the app password
  4. The Content tab paginates through the user's own posts, replies,
     reposts, and likes; filter by content type, date, engagement, or
     keyword/alt-text
  5. The Patterns tab scans the accounts the user follows and explains each
     account; sort, filter, or bulk-unfollow as desired
  6. Sign out via the account menu (top-left); session token is cleared
     from Keychain

On the Content tab, likes whose original post is no longer reachable
appear with the text "Liked post no longer available." These are the
records described above. They may or may not be present on the demo
account, since they only exist if an author the account liked has since
deleted their account or been suspended; their absence is normal and
does not indicate a fault.

A demo account is provided in the App Review Information sign-in
fields (handle + app password). It is populated with sample posts,
replies, reposts, and likes so every Content and Patterns flow can be
exercised end to end. After sign-in, open the Content tab and tap
Refresh if the list is empty; the Patterns tab populates after
tapping Scan.

The app is not a social feed and has no posting, comments, chat, or public
profile browsing. Its widgets can show a small read-only recommendation from
public posts returned by Bluesky; the main app writes that snapshot locally,
and the widget extension makes no network requests.
